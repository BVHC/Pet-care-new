# Ghi chú kiểm thử — cô lập IT, kỹ thuật đã chứng minh

> Chuyển nguyên văn từ `CLAUDE.md` (mục *Testing*) ngày 2026-11-08. Quy ước chung: `docs/convention/backend/09-testing.md`. **Đọc trước khi tạo hoặc sửa một `*IT`.** Khi nhận một era mới, cập nhật số "next" ở đây **và** ở dòng tóm tắt trong `CLAUDE.md`.

- **Isolation between ITs:** each feature uses its own `MutableClock` era (year) and cleans only that era; rows get UUID emails or a per-test tag. A job whose scan has no lower bound (ST02, ST05, ST13, ST15, ST18 overdue, cleanup jobs) touches every older era, so an IT running it takes an era **older than all others**: `AccountFsmIT` 1998, `AppointmentFsmIT` 1997, `VaccineOverdueIT` 1990, `CareTaskFsmIT` 1989, `BoardingOverdueIT` 1988, `BoardingBookingFsmIT` 1987, `CashierShiftFsmIT` 1986, `OtpTokenCleanupIT` 1985, `NotificationCleanupIT` 1984, `RefreshTokenCleanupIT` 1983 → **next 1982**. An IT without such a job takes a **future** era nobody scans: `VisitFsmIT` 2028, `MainFlowE2EIT` 2029, `MainFlowExamIT` 2030, `OrderFsmIT` 2033, `KennelFsmIT` 2035, `RetailSaleFlowIT` 2036, `BoardingStayFlowIT` 2037, `BoardingVaccineGapIT` / `RefreshTokenIT` 2038 → **next 2039**.
- `audit_logs` rows cannot be cleaned by era: tag them with a random `reason` or narrow the time window. An IT that changes `system_configs` restores the V2 value and calls `SystemConfigService.reload()` (exception: `session.access_ttl_minutes` is **720** in the `test` profile via `src/test/resources/db/test-migration/V9000`, so ITs that move the clock keep their tokens alive; production default 10; `RefreshTokenIT` sets 10 and restores 720, `SystemConfigIT` expects 720). An IT that deletes `sessions` first deletes their `refresh_tokens` (FK `RESTRICT`); one that edits `notification_templates` restores `subject = default_subject, body = default_body`. An IT that inserts `prescription_items` or a medical record for an appointment-based visit deletes them itself before `AppointmentItSupport.cleanUp` (`VaccinationItSupport.deleteDoses`).
- **Proven techniques (copy the template):** race = hold a row / advisory lock in another thread and wait on `pg_stat_activity` (`whileHeld` in `BookAppointmentIT`, `StaffRoleTransferIT`) · rollback on failure = temporary trigger rejecting an INSERT / UPDATE (`InAppNotificationIT`) · no connection during BCrypt = `HikariPoolMXBean.getActiveConnections() == 0` in a spy `PasswordEncoder` (`LoginIT`) · index proof = `EXPLAIN` on 20 000+ rows in a rolled-back tx + `ANALYZE` (`NoShowIT`) · no write = compare `xmin` (`BookingRestrictionIT`) · unbuilt module = `@Primary` SQL stand-in for the `api` interface (`JdbcPetCustomerModule`) · jobs = era data, failing batch, `SKIP LOCKED` vs a held row (`AppointmentReminderIT`) · SMTP = GreenMail :3025 (`NotificationOutboxIT`).
