# Giao dịch, khóa, đồng thời — quy ước nhà

> Chuyển nguyên văn từ `CLAUDE.md` (mục *Transactions, locking, concurrency*) ngày 2026-11-08 để CLAUDE.md nhẹ hơn. **Đọc file này trước khi viết hoặc sửa bất kỳ luồng ghi, job hoặc khóa nào.** Bản tóm tắt luôn nạp: `CLAUDE.md`. Quy ước chung: `docs/convention/backend/07-transaction-management.md`. Khi đổi thứ tự khóa hoặc thêm advisory namespace, sửa **ở đây** (và ghi ADR).

Every write ADR follows these. Read the ADR of the neighbouring feature before writing a new flow.

- **One `@Transactional` per use case** on the service. No `noRollbackFor` except for a committed failure counter (OTP, login, current password); such exceptions are thrown directly inside that method, after its writes. Never `catch` inside the tx: it becomes rollback-only and fails later with `UnexpectedRollbackException`.
- **Facade without a tx** when work must happen outside it: BCrypt (never hold a connection or a row lock during it); an audit after rollback; a cache reload after commit; catching an error that must not leak (forgot password always returns 202).
- **Order inside a use case:** authorize (role, then ownership / scope on an immutable projection) → lock → read under the lock (never `findById` before locking: the persistence context returns the stale entity; lock with a native scalar query or a projection) → `now = clock.instant()` after the locks (truncate to µs when returned and re-read) → guards → write → `saveAndFlush` / `flush` → audit and outbox → map.
- `findByIdForUpdate` emits **`FOR NO KEY UPDATE`** (Hibernate 6). FK checks only take `FOR KEY SHARE`, which does **not** conflict with it: a module inserting a row that points at a staff member or a pet must first lock that row `FOR SHARE` (`PetQueryApi.findPetForShare`, `accounts … FOR SHARE` for visit assignment / shift opening).
- Put `@Transactional(MANDATORY)` on repository lock methods too; otherwise a lock called outside a tx locks and releases immediately in autocommit.

- **Isolation:** default READ COMMITTED. Paged reads (count + page) use `readOnly` + REPEATABLE READ. A write that re-reads after waiting for a lock must stay READ COMMITTED — under REPEATABLE READ the re-read still sees the pre-lock snapshot (ADR-0061 M5).
- **Jobs:** keyset scan of ids (read-only, in the order of the index it uses) → **one record per tx** with `… FOR NO KEY UPDATE SKIP LOCKED` → re-check under the lock → conditional UPDATE (`WHERE status = …`, must hit 1 row) → outbox in the same tx; time budget ≤ 60 s. Long jobs pick a cron minute no other long job uses (ST20 HIGH needs a free thread).
- **Native SQL:** append only the conditions that were sent (never `:x IS NULL OR …` — it loses the index); keep status literals in the query so partial indexes match; bind `LocalTime` as `CAST(:t AS time)` from `toString()` (Hibernate truncates it to ms otherwise).
- No `lock_timeout` is configured: a deadlock (40P01) → `PessimisticLockingFailureException` → 409.
